P1 - Tutorial de OpenSees
Tutorial mínimo de OpenSeesPy para análisis estructural 3D
Recurso para el proyecto Laboratorio estructural digital interactivo Enfoque: modelos 3D lineales con vigas/columnas, verificación, cargas, diafragmas y extracción de resultados.

1. ¿Qué es OpenSeesPy?
OpenSees es un framework de análisis estructural y geotécnico. OpenSeesPy permite construir y ejecutar modelos OpenSees desde Python.

En este proyecto se utilizará principalmente para resolver modelos estructurales 3D del tipo:

 

y recuperar después:

desplazamientos;

reacciones;

esfuerzos internos;

deformaciones;

respuestas de sección.

El modelo global del edificio será lineal elástico. Más adelante se usarán modelos no lineales de sección de manera separada para construir curvas de capacidad.

3. Regla fundamental: OpenSees no tiene unidades propias
OpenSees trabaja solamente con números.

Por lo tanto, el usuario debe mantener un sistema de unidades consistente.

Para este proyecto se recomienda:

Magnitud	Unidad
longitud	m
fuerza	kN
tensión / módulo	kN/m²
momento	kN·m
área	m²
inercia	m⁴
Por ejemplo:

E = 25.0e6  # kN/m² = 25 GPa
Una causa extremadamente común de resultados absurdos es mezclar:

m con mm;

kN con N;

MPa con kN/m².

Regla de trabajo
Definir las unidades antes de programar el modelo.

5. Primer modelo 3D: viga en voladizo
Construiremos una viga horizontal de longitud L, empotrada en un extremo y cargada verticalmente en el otro.

La viga se encuentra sobre el eje global X.

5.1. Crear el modelo 3D
import openseespy.opensees as ops

ops.wipe()

ops.model(
    "basic",
    "-ndm", 3,
    "-ndf", 6,
)
Significa:

ndm = 3: tres dimensiones espaciales;

ndf = 6: seis grados de libertad por nodo.

Para este tipo de nodo:

DOF	Variable
1	u_X
2	u_Y
3	u_Z
4	\theta_X
5	\theta_Y
6	\theta_Z
6. Crear nodos
L = 3.0

ops.node(1, 0.0, 0.0, 0.0)
ops.node(2, L,   0.0, 0.0)
La sintaxis conceptual es:

ops.node(nodeTag, X, Y, Z)
El nodeTag debe ser único.

Una buena práctica es separar el identificador del nodo de sus coordenadas:

nodes = {
    1: (0.0, 0.0, 0.0),
    2: (3.0, 0.0, 0.0),
}

for tag, xyz in nodes.items():
    ops.node(tag, *xyz)
Este patrón será mucho más útil cuando el edificio tenga cientos o miles de nodos.

7. Apoyos y restricciones
Empotramos el nodo 1:

ops.fix(1, 1, 1, 1, 1, 1, 1)
Cada número indica si un GDL está restringido:

1: restringido;

0: libre.

Por ejemplo:

ops.fix(10, 1, 1, 1, 0, 0, 0)
restringe las tres traslaciones pero deja libres las tres rotaciones.

Importante
Nunca interpretar un apoyo solamente por cómo “se ve”.

Un apoyo en OpenSees es una lista explícita de restricciones de GDL.

8. Propiedades de la sección
Usaremos una sección rectangular:

b = 0.30
h = 0.50

A = b * h

Iy = b * h**3 / 12.0
Iz = h * b**3 / 12.0
En este ejemplo queremos que:

local y sea paralelo a global Y;

local z sea paralelo a global Z.

Por eso:

 

representa la inercia asociada a flexión por desplazamiento en dirección local z.

Definimos propiedades elásticas:

E = 25.0e6       # kN/m²
nu = 0.20
G = E / (2.0 * (1.0 + nu))
Para la torsión necesitamos J:

J = 0.002
En un modelo real, J debe calcularse de manera consistente con la geometría de la sección.

9. Ejes locales: la parte que más errores produce
Para elementos de viga-columna 3D no basta con conocer los nodos I y J.

El eje local x queda definido por:


pero todavía falta definir cómo se orientan y y z.

Para ello OpenSees utiliza un vector vecxz.

transf_tag = 1

ops.geomTransf(
    "Linear",
    transf_tag,
    0.0, 0.0, 1.0,
)
En este caso:

vecxz = (0, 0, 1)
Para nuestra viga paralela al eje global X:

local x = global X
local y = global Y
local z = global Z
Regla crítica
El vector vecxz no puede ser paralelo al eje local x del elemento.

Por ejemplo, para una columna vertical cuyo eje local x es aproximadamente global Z, no se debe usar:

vecxz = (0, 0, 1)  # incorrecto para una columna vertical
Una alternativa podría ser:

vecxz = (1, 0, 0)
En el proyecto
Los ejes locales deben visualizarse, no suponerse.

11. Aplicar una carga nodal
Aplicaremos una fuerza de 10 kN hacia abajo:

P = 10.0

ops.timeSeries("Linear", 1)
ops.pattern("Plain", 1, 1)

ops.load(
    2,
    0.0,   # FX
    0.0,   # FY
    -P,    # FZ
    0.0,   # MX
    0.0,   # MY
    0.0,   # MZ
)
La carga nodal tiene seis componentes porque el nodo tiene seis GDL.

12. Configurar un análisis estático
ops.constraints("Plain")
ops.numberer("RCM")
ops.system("BandGeneral")
ops.algorithm("Linear")
ops.integrator("LoadControl", 1.0)
ops.analysis("Static")
Luego:

ok = ops.analyze(1)

if ok != 0:
    raise RuntimeError("El análisis OpenSees falló")
analyze() retorna 0 si el análisis termina correctamente.

Importante
Que analyze() retorne 0 significa:

el algoritmo logró resolver el problema numérico definido.

No significa:

el modelo representa correctamente la estructura real.

14. Primera verificación analítica
Para un voladizo Euler-Bernoulli con carga P en la punta:


Usamos magnitud positiva para comparar:

delta_ref = P * L**3 / (3.0 * E * Iy)

print("OpenSees :", abs(uz))
print("Analítico:", delta_ref)

error_rel = abs(abs(uz) - delta_ref) / delta_ref

print("error relativo =", error_rel)
Una prueba automática:

assert error_rel < 1.0e-10
Este assert vale mucho más que simplemente mirar una deformada y decidir que “parece correcta”.

16. Fuerzas de elemento
Una forma de consultar la respuesta de un elemento es:

global_forces = ops.eleResponse(1, "globalForce")
local_forces  = ops.eleResponse(1, "localForce")

print("global =", global_forces)
print("local  =", local_forces)
Advertencia importante
La interpretación del vector retornado depende del elemento y del tipo de respuesta solicitada.

No escribir código como:

M = ops.eleResponse(1, "localForce")[5]
sin haber validado antes:

qué componente es;

en qué extremo;

con qué signo;

en qué sistema de coordenadas.

En el proyecto se deberá documentar explícitamente el contrato utilizado para convertir la respuesta de OpenSees a diagramas.

17. Script completo del primer ejemplo
import openseespy.opensees as ops

# ------------------------------------------------------------
# 1. Modelo
# ------------------------------------------------------------

ops.wipe()
ops.model("basic", "-ndm", 3, "-ndf", 6)

# ------------------------------------------------------------
# 2. Geometría
# ------------------------------------------------------------

L = 3.0

ops.node(1, 0.0, 0.0, 0.0)
ops.node(2, L,   0.0, 0.0)

ops.fix(1, 1, 1, 1, 1, 1, 1)

# ------------------------------------------------------------
# 3. Material / sección
# ------------------------------------------------------------

b = 0.30
h = 0.50

A = b * h
Iy = b * h**3 / 12.0
Iz = h * b**3 / 12.0

E = 25.0e6
nu = 0.20
G = E / (2.0 * (1.0 + nu))

J = 0.002

# ------------------------------------------------------------
# 4. Transformación
# ------------------------------------------------------------

ops.geomTransf("Linear", 1, 0.0, 0.0, 1.0)

# ------------------------------------------------------------
# 5. Elemento
# ------------------------------------------------------------

ops.element(
    "elasticBeamColumn",
    1,
    1, 2,
    A,
    E,
    G,
    J,
    Iy,
    Iz,
    1,
)

# ------------------------------------------------------------
# 6. Carga
# ------------------------------------------------------------

P = 10.0

ops.timeSeries("Linear", 1)
ops.pattern("Plain", 1, 1)

ops.load(
    2,
    0.0, 0.0, -P,
    0.0, 0.0, 0.0,
)

# ------------------------------------------------------------
# 7. Análisis
# ------------------------------------------------------------

ops.constraints("Plain")
ops.numberer("RCM")
ops.system("BandGeneral")
ops.algorithm("Linear")
ops.integrator("LoadControl", 1.0)
ops.analysis("Static")

ok = ops.analyze(1)

if ok != 0:
    raise RuntimeError("Falló el análisis")

# ------------------------------------------------------------
# 8. Resultados
# ------------------------------------------------------------

uz = ops.nodeDisp(2, 3)

ops.reactions()
Rz = ops.nodeReaction(1, 3)

local_force = ops.eleResponse(1, "localForce")

# ------------------------------------------------------------
# 9. Verificación
# ------------------------------------------------------------

delta_ref = P * L**3 / (3.0 * E * Iy)

error_rel = abs(abs(uz) - delta_ref) / delta_ref

print(f"uz OpenSees       = {uz:.8e} m")
print(f"|uz| analítico    = {delta_ref:.8e} m")
print(f"error relativo    = {error_rel:.3e}")
print(f"Rz                = {Rz:.6f} kN")
print(f"localForce        = {local_force}")

assert error_rel < 1.0e-10
assert abs(Rz - P) < 1.0e-10
18. Cargas distribuidas sobre vigas
Para el proyecto será necesario transformar áreas tributarias en cargas lineales.

Por ejemplo:

$$
w = \frac{qA_t}{L}
$$
 

donde:

q: carga superficial;

A_t: área tributaria;

L: longitud de la viga.

En OpenSees una carga distribuida sobre un beam-column se aplica con eleLoad.

En 3D:

ops.eleLoad(
    "-ele", ele_tag,
    "-type", "-beamUniform",
    Wy, Wz, Wx,
)
donde:

Wy: carga por unidad de longitud en eje local y;

Wz: carga por unidad de longitud en eje local z;

Wx: carga por unidad de longitud en eje local x.

Por ejemplo, si la orientación del elemento fue definida de manera que:

local z = global Z
una carga gravitacional hacia abajo puede ser:

ops.eleLoad(
    "-ele", 101,
    "-type", "-beamUniform",
    0.0,
    -18.5,
    0.0,
)
Error típico
Suponer que Wz significa siempre global Z.

No.

beamUniform trabaja en los ejes locales del elemento.

Por eso la visualización de ejes locales es una funcionalidad obligatoria del proyecto.

19. De área tributaria a eleLoad
Supongamos:

q = 6.0       # kN/m²
Atrib = 12.0  # m²
L = 4.0       # m
Entonces:

W_total = q * Atrib
w = W_total / L

print(w)
Resultado:

18 kN/m
La verificación fundamental es:

assert abs(w * L - q * Atrib) < 1.0e-12
En el proyecto debe conservarse:

$$
\boxed{ \text{carga sobre la losa} = \text{carga transferida a vigas} }
$$
 

dentro de la tolerancia numérica adoptada.

  ↓
OpenSees
Esto permitirá usar los mismos datos en Unity.

21. Función para construir un elemento
def add_elastic_beam_column(
    ele_tag,
    node_i,
    node_j,
    section,
    transf_tag,
):
    E = section["E"]
    nu = section["nu"]

    G = E / (2.0 * (1.0 + nu))

    ops.element(
        "elasticBeamColumn",
        ele_tag,
        node_i,
        node_j,
        section["A"],
        E,
        G,
        section["J"],
        section["Iy"],
        section["Iz"],
        transf_tag,
    )
Después:

sec = sections["B30x50"]

add_elastic_beam_column(
    101,
    1,
    2,
    sec,
    1,
)
Este tipo de abstracción es ideal para trabajar con agentes de IA porque permite definir contratos claros.

22. Transformaciones diferentes para vigas y columnas
En un edificio 3D probablemente no todos los elementos usarán el mismo vecxz.

Por ejemplo:

# Vigas horizontales:
ops.geomTransf("Linear", 1, 0.0, 0.0, 1.0)

# Columnas verticales:
ops.geomTransf("Linear", 2, 1.0, 0.0, 0.0)
Pero esto no debe copiarse ciegamente.

La orientación final depende de:

dirección I → J;

vecxz;

convención geométrica adoptada.

Recomendación
Crear una función que calcule y exporte explícitamente los tres ejes locales de cada elemento para visualizarlos en Unity.

23. Diafragmas rígidos
Un diafragma rígido introduce relaciones cinemáticas entre nodos.

Para un piso horizontal en el plano global X-Y, la dirección perpendicular es global Z:

ops.rigidDiaphragm(
    3,
    retained_node,
    *constrained_nodes,
)
3 indica la dirección perpendicular al plano rígido.

La documentación de OpenSees recomienda utilizar el manejador:

ops.constraints("Transformation")
cuando se utilizan estas restricciones multipunto.

Interpretación
Un diafragma rígido horizontal no significa que todos los nodos tengan idéntico desplazamiento X,Y.

Si existe rotación alrededor de Z, un punto distante del centro puede moverse diferente.

La relación rígida incluye:

traslación del nodo retenido;

rotación del diafragma;

posición relativa de cada nodo.

29. Extraer resultados para Unity
Una estrategia útil es convertir los resultados inmediatamente a estructuras Python simples.

Ejemplo:

def extract_node_displacements(node_tags):
    out = {}

    for tag in node_tags:
        out[str(tag)] = list(ops.nodeDisp(tag))

    return out
Reacciones:

def extract_reactions(node_tags):
    ops.reactions()

    out = {}

    for tag in node_tags:
        out[str(tag)] = list(ops.nodeReaction(tag))

    return out
Respuesta de elementos:

def extract_element_local_forces(element_tags):
    out = {}

    for tag in element_tags:
        out[str(tag)] = list(
            ops.eleResponse(tag, "localForce")
        )

    return out

35. wipe() vs reconstrucción del análisis
Para principiantes, la estrategia más segura entre casos independientes es:

ops.wipe()
y reconstruir el modelo.

wipe() elimina el dominio completo.

Existe también:

ops.wipeAnalysis()
que elimina solamente los componentes del objeto de análisis, pero mantiene el dominio/modelo.

No confundir ambos.

39. ¿Qué debe hacer la IA y qué debe hacer el estudiante?
Un agente puede ayudar a:

convertir datos a OpenSees;

generar funciones;

escribir tests;

exportar JSON;

crear visualizadores;

refactorizar;

detectar inconsistencias de software.

Pero el estudiante debe determinar:

qué representa el modelo;

qué ejes son correctos;

qué apoyo corresponde;

cómo se transfiere una carga;

si un signo tiene sentido;

qué resultado verificar;

si la respuesta es físicamente plausible.
